The complete immutable attempt last-message JSON matches the archived report; the problem is authentication of clipped output, not evidence of fresh review.

`reviewable.patch` changes only `tools/physics-autopilot/stages/refuter-continuations.mts`. No actual shared tool was edited. Its optional `original_last_message` requires the exact canonical previous native attempt filename, positive integer attempt, matching evidence tag, SHA256-bound bytes, and parsed JSON equality with the independently hash-bound original report. Native receipt identity/hash, report hash, clipped diagnostic suffix and 256-character minimum remain mandatory. Without the new binding, legacy header checks remain unchanged. A supplied optional binding is validated even when the receipt already contains full JSON.

The proposed binding is in `authorization-extension.proposal.json`; it is not a live authorization and does not supersede the withdrawn authorization. Root must review installation authority separately. No report/receipt formatting, tail, findings, original observations or current coverage were changed. The proposal authenticates the original report only; all fourteen fresh reads remain owed to the genuine native continuation.
