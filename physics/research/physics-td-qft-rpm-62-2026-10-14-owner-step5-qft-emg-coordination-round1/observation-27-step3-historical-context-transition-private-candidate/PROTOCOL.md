The only decision changes admitted are the receipt seals and, for those five reviewed uses, consumer math hash and appended review references. Context entries are checked against the exact owner proposal; its preserved old-context selection must match the genuine archive. Only explicit premise quotes, consumer hash, and review evidence text/appended refs may evolve. Existing context input bindings cannot be replaced; additions must be separately bound same-owner science.

The helper calls the existing `externalContextReceipt` on every current accepted row and requires its exact returned seal. This retains native literal used-clause, explicit consumer-premise, current supplier/consumer guard, published maintenance and original finding validation. It does not call a stamping command or replace any original subject hash.

The native evidence is the genuine completed `impact-repeat` certificate and its exact tool dispatch. Its payload, canonical path, run/phase/round and successful `autopilot` identity are checked; state must record the certification gate passed after that dispatch. Every refreshed consumer must occur exactly once in the certificate with the current raw source and item guard. This is selected current consumer content verification, not a new whole-library context hash or a blanket statement that every historical evidence path remains current.

## Step3 verifier integration

`step3-close verify` retains the exact artifact-set and ledger-hash/count tests. Only the one changed decision artifact can supply a verified historical/current pair from the helper; every other raw artifact mismatch still fails. A missing pointer preserves the old behavior. A malformed/stale transition fails rather than bypassing the ordinary error. The historical decision preimage is accepted only when its raw guard equals the closure's original artifact guard.

Before ledger projection, `taxonomyOwnership` authenticates all run rows and every taxonomy-only lineage and unchanged substantive field. Any error fails. Historical verification then omits only validated taxonomy-only successor rows and retains all original rows; the projected hash/count must still equal the original immutable closure. Ordinary substantive successor rows are not excluded. The original `close` path records its actual current rows and is not invoked or used to reseal this run.
