# Initial owner handoff review withdrawal

This explicit owner recovery applies only at the paused, drained first 5.2 owner hold, before first collection or a subsequent owner pass. The first pack must have the three ordinary native units; unit1 must have no decisions or creations. It withdraws **every** assigned unit1 review and repair acceptance together. It neither repairs missing historical metadata nor treats current metadata as the old bytes.

Use `previewOwnerReviewWithdrawal(root, run, payload)` for read-only validation. It builds prospective capture bytes in memory, validates the same complete boundary as recording, checks state/request stability, and writes nothing. `recordOwnerReviewWithdrawal(root, run, payload)` performs the explicit immutable recording. Both functions are exported by `tools/step5-owner-review-withdrawal.mjs`. The exact payload has four fields:

```json
{
  "reason": "An explicit owner explanation of at least 80 characters describing the unavailable old supporting bytes and total credit withdrawal.",
  "recovery_manifest_file": "research/RUN-owner-step5-supporting-pin-recovery/recovery-manifest.json",
  "preparation_file": "research/RUN-owner-step5-impact-preparation-r2/owner-preparation.json",
  "preparation_inputs_file": "research/RUN-owner-step5-impact-preparation-r2/actual-metadata-and-inputs.json"
}
```

The recorder captures actual creation state/request, original pack, all three original native detailed reports and successful immutable attempt/result/prompt/log chains, the original unit1 persistent session, the complete original review and supporting-reference declarations, exact current supporting metadata archives, and the full current preparation source and manifest guard vectors. Every assigned target must occur exactly once in the full source vector; that vector must equal the complete actual run manifest scope. The recovery manifest must match precisely the stale subset of the original supporting declarations, authenticate any genuinely recovered bytes, and explicitly identify at least one unavailable preimage. The actual successful terminal prose may link the detailed report by a relative or absolute markdown target with any label. Genuine reported review counts are checked. Its exact final-message hash is captured. If a terminal instead contains structured fields, those present fields must agree with the detailed report; neither prose nor an abbreviated final invents row-reading evidence.

Recording creates `research/RUN-step5-v2/impact-initial-1-owner-review-withdrawal.json` and its immutable capture directory. It changes no native report, source, manifest, runtime state, review decision, audit, or gate result. Existing normal behavior is unchanged when this record is absent.

At first deferred collection, ordinary report validation still validates the original physical actions. Only the authenticated original unit1 supporting references are withheld from old-support adoption. Its original reviews and all supporting declarations remain verbatim historical fields in the receipt, with zero review/repair acceptance. Physical changes, actual Statement events, downstream observations, ledger proposals, and other units' genuine creations remain intact. The collection freezes every capture binding; later source repairs can leave this historical evidence valid without pretending it covers the new current source.

All original assigned unit1 IDs acquire mandatory current-review obligations owned by that same persistent native session. Initial source reviews, incidental sibling lanes, old unit1 rows, previous certification, or deleted operational carries cannot satisfy them. A one-time authenticated review-credit transition allows the first next pass even when source bytes and assignment sets are unchanged; it does not authorize another same-state retry. Ordinary impact propagation continues, including the historical physical Statement event when a later genuine root repair changed its current post hash. Fresh evidence must be a later successful immutable completion in the original session, bind the next pack and withdrawal, and carry the exact full current detailed review row. A structured fresh final cannot disagree with uncertainty or any other present full-row field.

Completed impact verification independently recomputes these duties and pins genuine fresh native report/result/attempt/log/prompt evidence. Certification, including cached certification paths, still requires completed ordinary impact closure. Missing fresh coverage never receives certification through this recovery. Scientific repair-cycle limits, current context checks, source validation, ordinary metadata checks, and the full gate battery remain unchanged.
