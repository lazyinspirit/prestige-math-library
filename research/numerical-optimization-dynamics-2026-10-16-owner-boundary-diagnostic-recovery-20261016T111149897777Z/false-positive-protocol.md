## Required focused review

1. Read the flagged item's entire current Statement/Definition and Proof/Verification, its exact worksheet row, and any actual suppliers needed to resolve that boundary. A detector is a candidate, not a mathematical verdict. Record the item-specific hypothesis, proof step/formula, status branch, or counterexample that resolves the signal. Preserve the richest approved scope; missing proof obligations require a sound repair rather than a blanket exemption.
2. `empty` flags only detect an indexed family, sum, product, union or related text in the item's claim. Determine whether the actual indexing set can be empty, whether positive dimension/cardinality excludes it, and what the empty aggregate means. A finite explicitly nonempty sum can be a false positive; a generic 'finite-dimensional' sentence alone does not settle it.
3. `zero` flags detect symbolic division in the proof. Trace each actual denominator and its admissibility/positivity/invertibility hypotheses, including zero-dimensional or zero-budget branches where relevant. A strictly positive denominator justified before division may uphold `not_applicable`; an unhandled admissible zero case requires proof repair.
4. `iff-forward`/`iff-reverse` flags inspect the item's own claim, excluding Facts & Assumptions. Read whether the text states this item's logical equivalence or merely refers to an equivalence predicate/status in another construction. An actual iff needs both directions, with specific proof evidence; quoted dependency text and predicate names need distinct reasons.
5. A `checked` row crediting a nonexistent step must be repaired to the actual discharge, if present, or the missing proof obligation must be resolved. The `reviewed` shortcut does not apply to `checked` rows: the checked-row detector executes before that shortcut. Do not merely renumber a row without reading the cited argument.
6. Template clusters require examination of each affected item's actual boundary. Reuse can be legitimate when a shared sentence accurately describes genuinely identical obligations, but cross-item repetition is not itself evidence. No generic or mass uphold is authorized by this receipt.

## Tool adjudication interfaces (descriptive only; none written)

For a flagged `not_applicable` row, `tools/boundary-audit.mjs` reads `boundaries[i].reviewed = {upheld: true, by: <specific reviewer>, reason: <item-and-row-specific concrete reason>}`. The implementation accepts a nonempty reason of at least 40 trimmed characters; its code does not enforce attribution or source binding here, so reviewers must provide truthful attribution and current evidence independently. Such rows are shown in `upheld` and excluded from contradiction failure. This is for a genuinely correct current disposition after focused review, not for avoiding a missing mathematical argument. The tool does not support this escape for a falsely credited `checked` step.

For template review, the separate interface is `boundaries[i].template_review = {upheld: true, by: <reviewer>, reason: <specific reason>, item_sha256: <current itemHashGuard>, row_sha256: <current exact row hash>}`. The item guard excludes the whole verification frontmatter block (`tools/item-hash.mjs`). The row digest is SHA256(JSON.stringify({case,status,text})), where text is `reason ?? evidence ?? ''` in the detector. A valid review also needs its normalized reason reused across fewer than `--min-cluster` distinct items (default 3). Both current guards and a concrete, nonboilerplate reason are required. Root owns any later binding; this task generated no independent adjudication hashes or canonical changes. Native full diagnostic output includes the tool's own row digests unchanged.

The template and contradiction mechanisms are independent: a reviewed contradiction does not automatically clear a template cluster, and template review does not discharge a genuine contradiction. Preserve original rows/history and review evidence when repairing canonical worksheets and rebuilding the merged contract later under root control.
