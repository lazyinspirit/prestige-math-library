# Proposed honest native reporting-owner recovery

This is a design proposal only. The original repeat unit1 session was ephemeral and its home was deleted by dispatch. No code-only assertion may turn it into either the initial persistent session or a newly created session. The immutable old report/collection, physical source actions and all decision counts remain history.

At the actual paused/drained5.6 hold, before a next impact pack or progress record, a strictly opt-in owner record could bind the exact original repeat pack/collection, all three successful immutable native handoffs, exact old report/pending IDs, real old session_id with session_home:null, actual two supplier Statement changes, and current full source/context/manifest guard vector. It would explicitly authorize native reestablishment rather than resume, grant no current reading/review/repair/certification credit, and require every one of the original10 assigned sources plus all8 pending consumers to receive fresh current native review. Original report/collection bytes and counters are never rewritten.

The normal next owner pack would assign those18 sources to a fresh persistent reporting-owner unit1, with a separate explicit binding indicating new native context after lost ephemeral context. The first follow-up dispatch starts a new session in a dedicated phase/round home; it cannot supply --resume-session with the old missing ID. Only its actual successful immutable completion and full exact fresh detailed review rows can establish the new session identity. Incomplete, sibling, initial-source, wrong-session, stale-context or old report rows cannot close these recovery duties. Later follow-ups resume that actual newly established session. Evidence must bind the original history, explicit root authorization and actual fresh native execution without inventing continuity.

The normal future repeat base owners should start with phase/round-specific persistent homes, so a pending consumer can resume its genuine reporting reviewer. A distinct reporting-owner session field should leave the old initial reader-owner fields and homes unchanged. Initial withdrawal86, creator-helper physical history, existing genuine critical owner duties, ordinary current-context tests, source registration, collection licensing, scientific repair-cycle bounds and certification/gate checks remain unchanged. Conflicting ownership must produce an explicit hold rather than silently choosing a session by lane number.

Focused tests should reproduce the actual repeat phase with a new original session/null home, prove that wrong initial-session attribution fails, and prove that recovery admission itself grants zero coverage. Only actual fresh18 native rows in the dedicated new session should permit closure; missing source/consumer rows, wrong session, altered originals, unpaused/wrong stage/after next-pack creation and forged completion/certification should fail. Future genuine persistent repeat sessions should resume normally without this exceptional recovery record.
