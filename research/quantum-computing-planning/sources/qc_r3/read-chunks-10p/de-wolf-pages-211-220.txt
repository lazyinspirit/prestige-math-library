B.2
Algorithms and probabilities

• When we don’t care about constant factors, we’ll often use big-O notation: T(n) = O(f(n))
means there exist constants c, n0 ≥0 such that for all integers n ≥n0, we have T(n) ≤cf(n).
Similarly, big-Omega notation is used for lower bounds: T(n) = Ω(f(n)) means there exist
constants c, n0 ≥0 such that T(n) ≥cf(n) for all n ≥n0. T(n) = Θ(f(n)) means that
simultaneously T(n) = O(f(n)) and T(n) = Ω(f(n)). Such notation is often used to write
upper and/or lower bounds on running time of algorithms as a function of input-length n.

• For N = 2n, we can identify the integers {0, . . . , N −1} with their n-bit binary representations

• A randomized algorithm is a classical algorithm that can flip random coins during its op-
eration, meaning its behavior is partially determined by chance and its output is a random
variable that depends on its input, rather than a deterministic function of its input. One can
think of a randomized algorithm as a probability distribution over deterministic algorithms
(one deterministic algorithm for each setting of the coins).

• When we say a (randomized or quantum) algorithm has error probability ≤1/3, this typically
means in the worst case: for every possible input, the algorithm produces the correct answer
with probability ≥2/3, where probability is taken over the random coin flips and/or quantum
measurements during its operation. Such statements do not refer to “most” inputs under some
distribution on the inputs, unless stated explicitly.

• If a (randomized or quantum) algorithm produces the correct answer in expected running
time T (meaning for each input its expected running time is ≤T), then we can convert that
into an algorithm with worst-case running time 3T and error probability ≤1/3, as follows.
Run the original algorithm for 3T steps, and just cut it off if it hasn’t terminated by itself.
The probability of non-termination within 3T steps is at most 1/3 by Markov’s inequality.
Hence with probability ≥2/3 we will have received the correct answer from the algorithm.

• The union bound is very useful for analyzing an algorithm with T randomized subroutines,
each of which has its own small failure probability ≤1/(3T). If these failure events are inde-
pendent, then the probability that none of the T subroutines fails is at least (1 −1/(3T))T ≥
1 −T/(3T) = 2/3 (using the last bullet of B.1). But what if these events are dependent on
each other, which may well happen if the subroutines depend on what happens elsewhere in
the algorithm? Then by the union bound, the probability that one or more of the subroutines
fails is ≤T · 1/(3T) ≤1/3. In other words, the probability that none of the T subroutines
fails is still ≥2/3.

• If a (randomized or quantum) algorithm with 0/1-outputs has error probability ≤1/3, then
we can cheaply reduce this error probability to small ε > 0, as follows. Choose odd n =
O(log(1/ε)) such that 2e−2α2n ≤ε for α = 1/6. Run the original algorithm n times, each
time with newly-chosen randomness, and output the majority among the n output bits. The
probability that this majority is wrong (i.e., that the number of correct output bits is more
than αn below its expectation), is at most ε by the Chernoff bound.
