# Scoped Step2 metadata reconciliation proposal

From repository root, run `node research/machine-learning-all-101-2026-10-19-owner-step2-metadata/your-proposal/reconcile.mjs` (dry run by default). Every invocation creates a fresh proposal snapshot with immutable before/proposed files, full-file input SHA guards, per-field before/after operations, exact current page inventories, dependency order, and explicit errors. No actual carriers change.

Source frontmatter is authoritative for manifest id/kind/title/deps/justified_by/forward_refs; identity conflicts fail closed rather than renaming. Existing manifest statement keys mirror the entire exact current primary section, excluding its following references section. Absent statement keys remain absent. Remarks use their first substantive heading. Missing optional source lists delete stale manifest mirrors, never source dependencies. Source files change only through literal scalar dependency_level insertion/replacement; every body and unrelated frontmatter byte is preserved.

Levels use the unchanged native `item-dependency-levels.mjs` rule: only deps within the exact run inventory raise levels. justified_by and forward_refs remain distinct mirrored relations. Cycles, missing canonical dependency files (including unresolved aliases needing explicit review), missing sources, duplicate ownership and page placement defects block apply. External contexts receive existence checks only, no proof or metadata audits. Extra page placement context is inventoried and retained. Only the exact 101 top-level batch1–101 pages manifests supply ownership; no global plan, stale nested archive, report or guessed source-run inventory is used.

Root must rerun after native writers and escalation integrations drain, inspect that snapshot's plan and proposed diffs, then explicitly execute `node research/machine-learning-all-101-2026-10-19-owner-step2-metadata/your-proposal/reconcile.mjs --apply-root-reviewed --plan <reviewed snapshot/plan.json>`. Do not use an older snapshot after source changes. Apply refuses any changed manifest inventory, guarded input or staged proposal, and independently restricts edits to allowed fields. It archives every changed actual file and the plan before any writes, rechecks all inputs, then replaces individual files using same-directory renames. Root must coordinate exclusive writers: the filesystem does not offer a multi-file atomic transaction, and an I/O failure may require root recovery from the archive. Reusing an apply archive is rejected.

The script performs no body edits, global-plan writes, receipts, hash-binding refresh, workflow transitions, readiness records, recertification, or gates. The companion `reconcile-proof-contracts.mjs` is separately owned and is not invoked. This packet grants no mathematical or native workflow credit.
