# Unchanged page repaired through its defining procedure

This predicate grants one exception to the Step 3 `decision-not-applied` unchanged-carrier guard. It grants no acceptance, scope, ledger, provenance, staleness, source-change or closeout exception. Install its call only beside `priorAppliedRepair` in that guard. Keep every ordinary native gate and the receipt evidence closure.

The supported case is a genuine same-batch refuter fatal page finding whose intended budget-status summary becomes true through a genuinely changed, owned algorithm already in that page's immutable inventory. The page remains byte-for-byte unchanged. The genuine completed native Alpha independently confirms and fixes both separate fatal findings with confidence 1 and explicitly records the causal repair and unchanged page review. Both distinct active ledger rows and original findings remain intact. This is neither duplicate-defect conversion nor a false-positive or prior-applied repair.

## Registry and arguments

The canonical existing owner-evidence document retains `version: 1` and `run`, and gains `unchanged_page_causal_repairs: []`. A matching entry has:

- `version: 1`, `policy: owner-step3-unchanged-page-causal-repair-v1`, actual `run`, `batch`, `owner_identity: /root`, `reviewed: true`, `type: procedure-budget-status-summary`, and a specific reason of at least 80 characters.
- Page `id`, `obligation`, `defect_id`, `current_path`, `current_raw_sha256`, `target_sha256`, `decision_sha256`, `ledger_row_sha256`.
- `cause` with the corresponding owned algorithm `id`, separate `obligation` and `defect_id`, `current_path`, `current_raw_sha256`, `current_carrier_sha256`, `target_sha256`, `decision_sha256`, `ledger_row_sha256`.
- Exactly thirteen named `refs`: `scope`, `post_snapshot`, `post_manifest`, `page_source`, `cause_before`, `cause_after`, `refuter_report`, `refuter_result`, `alpha_result`, `alpha_prompt`, `alpha_report`, `alpha_decisions`, `ledger_rows`. Each value is exactly `{path, sha256}`, references a regular file under `research/RUN-...`, and supplies a full lower-case SHA-256. No null hashes, symlinks, absolute paths, traversal or backslashes are accepted. `ledger_rows` is a JSON array of the two separate active rows.
- `relation.kind: budget-status-summary`, `status: budget-exhausted`, and exact literals `page_literal`, `before_literal`, `after_literal`, `complete_last_call_literal`, `consumer_causal_literal`, `report_literal`, `cause_review_literal`. These bind the unchanged claim, old/new Definition status rule, complete last-call certificate rule, both actual native decision reasons and the actual native report's explicit no-page-edit statement. Literals do not create or replace the native review.

`target_sha256` binds the complete normalized original target including `route: flagged`. The immutable normalized finding itself remains unchanged. Decision hashes use recursively key-sorted JSON after removing only the optional `subject_sha256` future stamp; all other current and archived decision-document fields must agree. Ledger-row and carrier hashes use recursively key-sorted JSON without exclusions. Raw file/ref hashes use the actual bytes. All sealing belongs to the root owner.

The caller supplies the existing actual `activeRows` projection, `currentCause` from the ordinary live fingerprint collection and the current `ownerEvidence` document. The predicate recomputes cause source/contract/manifest carrier, requires equality with `currentCause`, authenticates original POST source bytes, and verifies the unchanged current page against original POST page bytes, metadata and item order. It verifies actual single current ownership, and both causes/subjects must already belong to the immutable scope and original inventory.

Both native results must be completed, unaborted and successful. Immutable attempt and current alias result bytes must match the sealed receipt. The refuter result must contain the entire parseable original report in its tail; a clipped or reconstructed report is rejected. Alpha's authentic tail must identify the exact current report and decision paths; its genuine native prompt, report and decision archives are bound. The actual current semantic decision document must still equal the archived reviewed document except future subject stamps.

## Receipt closure

This proposal requires the separately installed `owner_repair_evidence_policy: step3-owner-repair-evidence-freeze-v1` receipt policy. That policy freezes the complete canonical owner-evidence document and recursively every own-run hashed reference, including all thirteen `unchanged_page_causal_repairs[].refs` values. The marker belongs to the receipt, not the owner-evidence registry. Live `current_path` and `cause.current_path` are canonical source paths, not archival reference objects; they are checked as current bytes and carriers here. This proposal does not modify the close/freezer code or waive any closure check.
