## Plan/design reconciliation — owner action needed

1. **Prerequisite page mismatch.** `plan-spec.json` declares only `marginal-likelihoods-bayes-factors-and-empirical-bayes` as the A-page `requires` entry. The BCS-18 track design says `Requires: BCS-03, BCS-06`. We follow the controlling page shell and therefore retain its BCS-06 edge; the scalar Gaussian calculation is proved here and does not import BCS-03's finite normal-normal theorem. No shared plan was edited.
2. **Open in-run page edge and scheduling mismatch.** The current batch assignment says batch 21 is level 0 with no prerequisite batches, but the A-page shell requires the BCS-06 page in batch 9. Recomputing the current manifests gives batch 9 level 4 (requires 5 and 8) and batch 21 level 5 (requires 9). `node tools/batch-dependency-levels.mjs check --run bayesian-computational-statistics-62` reports a stale artifact. The batch-specific cross-batch input records the page edge as `open`; the shared schedule artifact and owner state were left untouched. The actual batch-9 `def-type-ii-marginal-likelihood-and-empirical-bayes-posterior` body is a definition for finite-group dominated hierarchies, and it explicitly requires finite-positive evidence and an attained measurable maximizer. It states no generic sequence result or coverage guarantee. Its transitive page requirements are `posterior-propriety-and-dominated-bayes-formula` (batch 5) and `hierarchical-bayesian-models-and-partial-pooling` (batch 8); those in-run carriers are draft/in-flight. This batch uses no item-level claim from them: it supplies a sequence-specific model, selector domain and local posterior/evidence proof. The formal page-level `requires` edge remains open for owner reconciliation.
3. **Missing first-coordinate hypothesis.** The BCS-18 design's positive coverage statement omits `theta_{0,1}=0`. The final 2015 paper makes this a notational assumption throughout §2.1 and explains why it is necessary: the marginal likelihood does not use the first-coordinate value, but its posterior-mean bias does, so uniform coverage over unbounded first coordinates fails. The theorem carrier therefore includes `theta_{0,1}=0`. The sparse-gap carrier also verifies this condition. Owner must reconcile the shared design by adding this hypothesis or selecting the paper's alternative shifted prior convention; neither shared file was changed.
4. **Sparse-gap growth index.** The BCS-18 design uses `n_{j+1} >= (2 rho_j^2)^(1+2 beta+2p) n_j`; final Theorem 3.1 uses `rho_{j+1}`. The latter guarantees the next first gap starts beyond the preceding second gap. The counterexample and B-page example use the source's `rho_{j+1}` condition and the exact source interval endpoints `(N_j/rho_j, N_j]` and `(2N_j, rho_j N_j]`. Owner must reconcile this index difference in the plan.
5. **Integer-index convention.** The polished-tail definition writes an upper endpoint `rho N` for integer coordinates. This carrier makes the convention explicit as `floor(rho N)`; it changes no real-valued parameter or claim.
