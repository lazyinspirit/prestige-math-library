## What the existing tools actually do

`research/numerical-optimization-dynamics-2026-10-16-owner-final-metadata-preparation/reconcile.mjs` rebuilds derivations/routine_steps from source paragraphs, can assign new derivation IDs and default classifications, replaces inputs with regenerated tags/tokens, rebuilds citation arrays, replaces each quote with the entire chosen source section, and projects supplier_interfaces from complete fact paragraphs. Its optional phase maps authenticate a particular Step 2 before-source/application; they do not authenticate later native rewrites. Its companion `verify-projected.mjs` explicitly requires whole-paragraph claims and whole-source-section quotes. Those are this historical projection's stronger policies, not the native proof-contract rule. Preserve their Step 2 application/history; don't repurpose them as a Step 3 acceptance path.

Native `tools/proof-contract.mjs` permits any nonempty exact citation excerpt contained in the **named** permitted source section, modulo whitespace; it requires every actual fact/source pair and every explicitly cited fact/step input, and exactly one existing derivation/routine-step mapping per proof step. It does not demand whole-proof-paragraph claim identity or whole-section quote equality. Stable row IDs, classification, scores, existing inputs, citation `reviewed` fields, `risk_review`/`risk_reviews`, supplier interfaces, boundaries and smoke records are independent retained evidence, not generated text.

`tools/facts-block.mjs` currently permits citation sections Statement, Statement refuted, Definition, Example and Remark. It does **not** permit Proof. A native exact Proof 1.2 excerpt must never be broadened to the entire Proof or silently reassigned to Statement. Preserve the genuine short quote and report the section incompatibility for a focused source/schema disposition. Actual inspection found this example in current batch12: F9 of `thm-jacobian-and-hessian-vector-products-have-truncation-and-noise-bounds` (supplier `lem-variance-and-covariance-identities-for-random-variables`, quote `Since the probability measure has total mass one, $2|X|\le1+X^2$ makes $X$ integrable.`, source_section `Proof`). The exact owning contract ID should be read from the final drained carrier; this is a live observation, not a frozen failure or an instruction to rewrite it.

## Minimal usable preview

New `preview-only.mjs` has no apply mode. After actual drain, root selects only current affected batches and a fresh output identity, for example:

```sh
node research/numerical-optimization-dynamics-2026-10-16-owner-step3-metadata-handoff/preview-only.mjs --writers-drained --batches 12,69 --output-dir research/numerical-optimization-dynamics-2026-10-16-owner-step3-metadata-handoff/ROOT-drained-preview-NEW
```

The batch numbers above are an explicit selection example, not a claim that these two batches are the complete pending set. Select the actual pending set from root's writer/repair inventory. The flag is an attestation only; the script never pauses workers or infers drain from old reports. No preview has been run here.

The output is a small JSON-pointer proposal, with exact old/new values and raw read-input archives. It proposes only same-ID manifest dependency mirrors; additive native explicit fact/step inputs for an existing row whose current full paragraph still matches; and existing citation `uses` membership. It preserves valid local quotes byte-for-byte. It never rewrites a derivation claim, stable ID, score, classification or prior input; never changes review records; never creates/removes citation rows, changes supplier interfaces or resolves boundary/smoke/ownership issues. Ambiguous/new/obsolete steps, altered public claims, missing pairs, unsupported quote sections and undefined inputs are holds. Every operation on an item with a hold is withheld. A shortened native derivation claim is retained and held for identity review, not declared mathematically invalid.

Before root stages any write: inspect the actual coordinate proposal, clear holds through genuine owner evidence, compare every archived input byte-for-byte with live files, inspect a minimal patch, and ensure no native derivation/risk/score/quote field outside the explicit operations changes. Any subsequent writer change invalidates that preview. Root stages and applies its own reviewed patch; this script cannot apply one. Keep the original successful preview/application packet immutable; create a new identity on drift rather than rerunning over prior evidence.

Changes to kind/title/statement/inventory, new proof worksheets, supplier quotes, premise changes, rehomes, published repairs, scope, page requires and contract-risk conclusions require separate focused owner disposition. This preview intentionally does not automate them. Root owns native checking, readiness, hashing, decision sealing and recertification after final source/metadata stability.

## accepted_repair continuity is an additional obligation

`tools/step3-scope.mjs` checks that a touched `accepted_repair` still matches its immutable reader-post carrier. Its `riskReviewOnlyDelta` is narrow: raw item and manifest hashes must be unchanged, and stripping the current singular `risk_review` must reproduce the original contract hash. It does not excuse arbitrary risk edits, scores, citation-use changes, whole-section quote replacement, derivation changes or manifest reconciliation.

For another metadata delta, root must evaluate the actual policy in `tools/step3-owner-source-identical-continuity.mjs` and record a genuine `source_identical_acceptance_continuities` entry in the run owner repair evidence. Required evidence/navigation:

- Existing exact `accepted_repair` decision and obligation, touched route, not an added or stabilized target; immutable original target and reader-post/current carrier bindings. Do not change verdicts or relabel native batch histories.
- Genuine `research/R-step3-hash-B-post.json` (version2/run/B/label post), `research/R-dispatch/alpha-3a-batch-B.result.json`, `research/R-alpha-batch-B-3a.md`, and `research/R-alpha-batch-B-3a-order.task.md`. The actual result must be successful, non-timeout, cover B, completed and not aborted; the assignment must include the item. Bind a durable archive of the exact accepted decision, not an invented new native decision.
- Policy/version/run/id/obligation plus post_reader_carrier, current_carrier, target and accepted_decision bindings. Root supplies the actual required hashes; this handoff supplies none. Set `historical_manifest_delta_unknown:true` and `independent_execution_coverage_adopted:false` only with their literal meaning retained; unknown historical full manifests do not become newly observed evidence.
- Ordinary source continuity means identical raw item bytes. The metadata exception needs the **complete actual reader-post source preimage**, binding the reader-post raw hash; exact unchanged body; parsed changes limited to dependency_level, verification and provenance; and unchanged audited/verified/sources_checked/repair verification markers. A dependency, statement, assumption, proof-strategy, source or status change is outside that exception. A digest mismatch alone proves no metadata-only delta.
- For a validated same-ID rehome, preserve original native assignment/report/post batch B. Authenticate root before/after source archives and current home separately; only current manifest/contract lookup uses the new home.
- Exact current source deps/manifest deps and normalized public section/manifest statement correspondence; exact current contract/carrier binding; and the policy's actual focused strict proof-contract execution. It invokes the validator itself; an asserted receipt is insufficient. A no-proof definition/algorithm/remark may retain original/current null contracts under the policy; proof-bearing missing contracts do not qualify.

Root performs those checks and creates bindings only after the source and metadata are stable. A proof changed since reader-post cannot be called source-identical. A new content amendment needs the genuine routed owner/Alpha resolution instead; do not manufacture continuity or switch accepted_repair to amended_repair merely to silence a gate. This evidence retains an existing acceptance and supplies neither new worker coverage nor a waiver of current gates.
