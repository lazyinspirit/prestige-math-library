# One Step 3 refuter coverage correction per unit

The root-owned version1 `RUN-step3-refuter-continuations.json` may register a
nonempty set of distinct original refuter units, bounded by the original
stage's unit count. Units must be valid positive batch IDs present in that
stage. Each unit has exactly the existing label
`refute-UNIT-coverage-correction-1`. A second entry for the same unit, another
correction number, an unrelated unit or an oversized registry is invalid.

Keep every original per-unit authority, successful result, immutable archived
report, task, observation and attempt history intact. Adding another eligible
unit does not renew a completed unit's budget. Root archives and authorizes
registry extensions from genuine native evidence; this adapter creates no
registry entry, source read, mathematical acceptance or execution receipt.
Original report findings must not be trimmed, supplemented or relabeled.

All entries' archived authority is always validated: exact original result,
original raw report/full structured tail or supported clipped suffix, task and
registration fields. Current pre-dispatch report/scope/subject guards and the
one-attempt check apply only to the registered units actually selected in the
current pending dispatch plans. Thus completed correction27 remains validated
historically but does not block a pending correction83 because its new stable
result already exists or its canonical report now contains the genuine corrected
output. Conversely, attempting27 again still holds. Any completed fresh result,
including a failure, spends that unit's one correction and requires owner
resolution; adding another unit does not clear it.

The exported `refuterContinuations` retains its original three-argument
behavior: `beforeDispatch:true` without an explicit selection guards all entries.
The ordinary stage adapter supplies the selected pending plan coverage as the
fourth argument. Doctor descriptors do not spend or bypass a dispatch budget.
Each real plan changes only its registered label and task; role, covers, model,
output schema, required report, stage IDs and every other plan field remain
unchanged.

Coverage excludes every registered unit's old original stable result. Each
exact new stable correction result is admitted separately; attempt filenames,
other correction numbers and unrelated correction labels supply no coverage.
Ordinary unregistered sibling units retain their original stable result route.
A fresh result must still satisfy the native engine's successful result and
actual artifact/collection requirements; regex membership grants no success.

## Live dependency reload

`mathlib.step3.mts` dynamically imports this adapter with the same search/query
version it received from its parent import URL. Installing the adapter and this
small stage import change together prevents a newly versioned Step3 module from
retaining the old static child policy. The entire stage table and scheduling
semantics remain otherwise unchanged.

For an already-running strictly supervised run whose watched path is its own
`.autopilot/RUN` wrapper, root performs its separately authorized wrapper refresh
after installing/resealing the reviewed source changes. Root verifies the real
`stages-reloaded` event before retrying the held collection. This document does
not stop an engine, edit a runtime wrapper, reset counters, reload another run
or authorize any such action. Future adapter-only edits also need an actual
new parent Step3 module version; an event alone must not be mistaken for proof
that an unchanged versioned child import was reevaluated.

Root must recheck current bytes and genuine writer drain when registering a new
unit. Preserve completed unit27 exactly and append only the genuine unit83
entry, with original archives/task supplied by its evidence owner. This is one
fresh exact-scope reread/corrected-attribution opportunity per affected unit,
not an additional mathematical review stage or a waiver of native collection.
Mandatory native validation/battery and policy resealing remain root-owned;
optional tests are waived for this focused repair. No optional tests or gates
were run while preparing this proposal.
