## What the proposal does

* Requires root authorization JSON, the actual paused scaffold boundary,
  `pauseAfter: 1-scaffold`, ended native dispatches, and (for application)
  actual root-supplied final mathematical-writer drain evidence.
* Keeps the 109 batch identities and 218 original page obligations. Inserts
  ONLY explicitly included helper IDs at their explicitly approved existing
  page/batch home, with named genuine acceptance/adoption evidence. Hold and
  context decisions leave those carriers outside the frontier.
* Uses the renderer's YAML module and the existing `sourceSectionText` parser.
  Copies actual canonical metadata/defining sections, including the full
  imported-input wording when it is part of that defining section. It does
  not invent a Statement, proof, quote, source-reading stamp or acceptance.
* Recomputes item levels through the existing `dependencyLevels` export and
  changes only the item YAML envelope. An assertion compares the entire
  original and resulting argument body for exact equality.
* Repairs ONLY the two specifically diagnosed truncated batch-6 page YAML
  envelopes; aligns page inventories/requires and preserves empty page bodies.
  A nonempty summary or another malformed envelope makes it stop.
* Updates the controlling plan only for explicit root-approved `requires`
  overrides, surgically preserving all other plan bytes. It does not
  transcribe Step-2 plan item inventories early.
* Calculates a complete proposed mutation set before writing, guards every
  read input against concurrent change, archives each changed preimage once,
  then uses atomic per-file replacements. Reapplication is idempotent; old
  preimages and prior application receipts are never overwritten. A source
  race stops application rather than silently using a moving input.

Root owns all hashes when root executes this proposal. The proposal author
has not calculated or compared source/receipt hashes. The syntax check does
not certify application semantics or successful current-frontier integration.

This is a shape illustration, not an acceptance or placement of an example ID:

```json
{
  "version": 1,
  "run": "inverse-problems-knot-theory-all-109-2026-10-19",
  "authorized_by": "/root",
  "all_mathematical_writers_drained": true,
  "drain_evidence": ["research/ACTUAL-FINAL-DRAIN-RECEIPT.json"],
  "helpers": [
    {
      "id": "lem-EXACT-ADOPTED-ID",

      "page": "actual-approved-existing-page",
      "reason": "Actual accepted scope and intended home",
      "acceptance_evidence": ["research/ACTUAL-OWNER-ADOPTION.json"]
    },
    {
      "id": "lem-EXACT-HELD-ID",
      "disposition": "hold",
      "reason": "Exact continuing hold; preserve draft/context"
    }
  ],
  "requires_overrides": {},
  "canonical_metadata_overrides": {},
  "manifest_metadata_overrides": {}
}
```

The optional per-ID `canonical_metadata_overrides` permits ONLY `deps`,
`sources`, `provenance`, and `axiom_use`. The deps value is the FULL explicit
root-chosen provider-ID array; source URLs are not dependency IDs. Sources and
provenance are explicit objects supplied by root, not automatically inferred
from a citation or import. Only `axiom_use` may be explicitly removed using
null. These edits occur before numeric levels and manifest mirrors are built,
so source and manifest describe the same chosen metadata. The entire item
argument/Facts body is compared byte-for-byte before accepting a proposed
source mutation. No linked provider is inserted merely because the scanner
found its name.

The optional per-ID `manifest_metadata_overrides` permits only `strategy`,
`external_inputs`, `source_reading_limits`, and `owner_metadata_note` supplied
truthfully by root. It cannot alter canonical arguments or claim native
authoring. `requires_overrides` supplies complete approved arrays, not edges
to be silently dropped. A page exceeding the 100-item capacity stops the
proposal and needs an actual supported scope/split decision.

After ALL writers drain and root has supplied decisions, root can first run
the proposal without `--apply` and inspect its exact mutation plan. The same
command with `--apply` performs only the metadata integration. For example:


This does not replace root's authentic contract/harvest/dependency-review
integration, current readiness renewal, final pre-gate preparation, fresh
