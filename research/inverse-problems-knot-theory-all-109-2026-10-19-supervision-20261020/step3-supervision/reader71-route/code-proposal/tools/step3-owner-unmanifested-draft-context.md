# Unchanged unmanifested draft context: explicit owner opt-in

This route handles a genuine native reader finding labelled `in-run-dependency` whose actual direct supplier is an own-run draft helper with **zero homes in every current run manifest**. It supplies read-only context to the already assigned consumer Alpha. It does not invent a producer batch, add a frontier item, broaden refuter coverage, adopt source reading, grant edit permission or accept mathematics.

Root registers `research/RUN-step3-owner-unmanifested-draft-context.json` with `{version:1,run,policy:"owner-step3-unchanged-unmanifested-draft-context-v1",authorized_by:"owner",authorization,contexts:[ENTRY]}`. Authorization is at least 40 characters. Nothing automatically writes this registry.

ENTRY fields:

- `version:1`, exact `run`, same `policy`, `owner_identity:"/root"`, `reviewed:true`, `mathematical_acceptance:false`, `edit_permission:false`, `coverage_adopted:false`.
- Actual `at` at or after successful native completion; concrete `reason` at least 80 characters. `batch` is the assigned consumer batch, `index` is the one-based original reader finding, `id` the helper, `consumer_id` the assigned consumer, and `finding_sha256` uses the existing exported `requiredPageHash` canonical JSON algorithm.
- Raw `{path,sha256}` own-run research references `findings` (immutable original complete findings JSON archive), `native_result` (exact original `reader-reader-B.attempt-N.result.json`), `prompt` (its actual prompt), `reader_report` (exact canonical `research/RUN-reader-B.md` prose report, bound by its actual raw hash; arbitrary own-run prose archives are rejected), `observed_source` (exact complete helper source), `consumer_source` (captured actual consumer source), `consumer_manifest` (captured actual owning manifest). When the manifest is archived, `consumer_manifest_original_path` is its exact canonical `research/RUN-batch-B.pages.json` origin.

The complete structured native tail must equal the entire archived findings object. Native identity, role, single covered batch, successful process and terminal completion, prompt and chronology are mandatory. Clipped tails are deliberately unsupported. The immutable indexed finding must retain its original subject label, consumer and `observed_source.snapshot: current`; the observed raw hash must exactly equal the full archived source. The historical finding is never rewritten.

Both archived and current helper have exact ID, `status:draft` and exact `pipeline_run:RUN`. During active Step 3 its current **entire bytes** must equal the observed archive: metadata or body edits fail closed and require separately authorized ordinary owner repair, not this route. All run manifests are searched for homes; any target home or duplicate consumer home rejects. The consumer must have one current home in the named batch and directly list the helper in both actual source `deps` and its manifest item's `deps`. All four archived/current source and manifest dependency fields must be arrays consisting only of valid item IDs; YAML scalar strings are rejected, even when their text contains the helper ID. The captured consumer/manifest independently bind that same direct edge. Transitive reachability, `justified_by`, aliases, a run marker alone, or guessed ownership do not qualify.

The normalized scope finding uses the honest type `unmanifested-draft-dependency`, its exact binding, and an observed hash for the exact helper archive. `reportOnlyFinding` restores the original native label when comparing against immutable native JSON. The scope adds **no** target to `manifest_post`, high-risk work, or `refuter_scope`. Collection validates this special reader context but does not pretend a native refuter read it. Order generation prints the actual read-only obligation and all limits instead of looking up a fictitious producer.

Alpha independently decides the ordinary `reader:B:N` obligation and retains `consumer_id`, one ordinary defect-ledger row, and the stamp of the actual current context carrier. The carrier binds the helper's raw and canonical hashes, owner entry, and current consumer source and manifest-item projection. Ordinary edits to the owned consumer can change its current seal while leaving the exact helper observation unchanged; removing the direct edge rejects. Alpha may not edit this context, accept it as a frontier item, accept a fatal fix, or use `context_accepted`. Only `false_positive`, `confirmed_nonfatal` or `escalated` are supported. A nonfatal decision requires `nonfatal-recorded`, not a repaired disposition. Escalation remains a normal blocker. The pre-existing evidence, ledger closure, per-obligation and final seal checks remain mandatory.

Step 3 closure freezes the registry and every exact native, historical source, consumer and manifest archive reference in its ordinary artifact map. During active Step 3 the route revalidates actual current context and edges. Once a real dependency-ordered v3 closure exists, historical verification reads only those frozen evidence files; later legitimate owner repairs do not become new Step 3 observations and are not rejected merely for changing a current context body. Ordinary closure artifact-hash comparison still rejects any registry or historical-evidence mutation.

No missing registry relaxes default behavior: the old out-of-scope diagnostic remains. No registry registration, state change, gate permission, review verdict, source edit or native decision is performed by these helpers. Root owns code integration, current module-closure resealing, actual drain/registration and normal native dispatch. Other finding classes and guards are unchanged.

Focused tests are isolated fixtures, including the actual scope lifecycle. They cover native-output/prompt tampering, missing or forged identity, edited source or run marker, invented/duplicate homes, missing direct edges, changed original finding, unsupported verdicts, missing/stale seals, ordinary consumer amendment, and historical closure versus later source repair. Run the candidate test file under `node --test` from the repository root; it overlays candidate tools into disposable fixture trees and never installs canonical code or registries.
