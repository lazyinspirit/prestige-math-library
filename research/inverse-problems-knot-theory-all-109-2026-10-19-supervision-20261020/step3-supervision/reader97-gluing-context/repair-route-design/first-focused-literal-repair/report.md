# One focused literal-replacement repair

The repaired-context FIRST implementation was independently accepted. This is its one focused repair of an actual root-registration failure, not a new mode or policy review.

`String.replace(search, replacementString)` interprets `$$`, `$&`, `$\`` and `$'`. In mathematical Markdown, a replacement containing `$$` therefore loses a dollar from each display delimiter; the resulting reconstruction differs from the actual after archive despite an honest exact proof edit. The one-line module proposal changes only `replace(edit.before,edit.after)` to `replace(edit.before,()=>edit.after)`, inserting the supplied source bytes literally. Uniqueness, proof-only reconstruction, before/after identity, review, native evidence, current-source and verdict guards are untouched.

Five regressions exercise the actual repaired-context validator using a complete synthetic root application/review/evidence chain. Each independently demonstrates that the old replacement-string operation yields different output, then verifies literal current-after acceptance for display-dollar pairs, matched-substring token, prefix token, suffix token and all four mixed. Every earlier current test is retained.

Actual isolated run:103 tests passed,0 failed, exit0 (`tests.stdout.txt`). Current canonical module and test were read-only compared with both archived preimages and matched when the final package was delivered. Root owns guarded application and actual registration retry; inventory owns the changed-passage final inspection. No canonical, registry, native-state, gate or source changes were made. Fixture-only hashes are part of the inherited isolated tests, not live recertification.
