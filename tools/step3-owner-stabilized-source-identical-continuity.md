## Revision2: strict native identity and noncircular certification

All own-run research refs reject absolute paths, backslashes, dot/dotdot/empty segments, missing/nonregular files, and **every** symlink component including ancestors. Raw refs hash actual bytes. Current native Alpha success additionally requires exact label3a-batch-B, integer attempt/evidence_tag agreement, task_aborted===false and final_response_present===true. Each native review adds `immutable_result:ref` pointing to the exact attempt result derived from evidence_tag/attempt; its actual bytes must equal the stable result alias. These explicit refs also enter closure freezing. Actual immutable creator results are checked under the same terminal/identity requirements.

Added helper creation_certification may use either an already existing exact hashed canonical ref or this narrowly typed declaration:

```
{path: "research/<run>-step3-auditor-certifications.json",
 required_current_native_certification: true}
```

Only those two keys and exact canonical path/true flag are accepted; no null hash, unknown flag/path, supplied certificate bytes or fabricated coverage is allowed. Before the first battery this is a **requirement**, not evidence claiming the certificate exists. The predicate still requires that exact real file at runtime and always invokes the current native certification loader with all original birth/origin/current-carrier checks. The genuine first native certification gate supplies it. Do not run certification early merely to fill an entry digest.

After the actual passed gate, the new closure marker resolves this exact declaration to the real current canonical native certification artifact and freezes its actual raw hash. Absence, a different path/flag, or changed bytes fail; no assumed certificate is frozen. Existing hashed-ref certification remains supported. This breaks the entry-sealing/first-certificate hash cycle without relaxing any origin or independent-review guard. Root chooses real report excerpts/proof identities; no new coverage is generated. The policy creates no certificate and does not execute native dispatches. The ordinary complete gate battery remains required.

Exact raw source bytes and per-item manifest carriers must match the authenticated pre-3a input. Valid compact manifest summaries remain unchanged; this policy does not extend the original-touched continuity policy or add optional claim projections. Only preserved review metadata and explicitly authenticated current supplier quotations may differ in the proof contract.

## Actual follow-up assignments

When a genuine later native assignment names an added helper or repaired supplier absent from the original static task, `assignment_kind: "native-dispatch-prompt"` binds that successful immutable attempt’s prompt as `assignment`. Its exact path must equal the actual result’s `prompt`, and the real assignment must name the subject. `original_assignment` separately binds the unchanged static task. No root-written replacement task supplies coverage. Without this explicit kind, the original static-task path remains required.

Preserved original full-proof reading and later focused attribution or body-identity acceptance retain separate provenance in the root binding. `proof_review_provenance` identifies the original genuine report/result/source and its session, the exact original proof-review excerpt and current focused-acceptance excerpt. A current session identifier never reattributes historical proof reading to the later session or claims a fresh reread.
