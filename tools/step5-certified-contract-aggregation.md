# Ordinary published closure and native certified aggregation

## Judgment obligations

Native selective Step 5 closure retains the complete frozen manifest, source and prerequisite context. The current certificate's original ordinary-published baseline exclusions are checked with `verifyInitialPublishedBaselineExclusions(..., {current:true})`. Only those authenticated unchanged successors have no new original-baseline judgment obligation. The output lists them separately as `historical_ordinary_published_exclusions`; they never enter `judge_coverage` or its verdict count. `summary.judge_scope` counts actual judgment obligations, while `summary.scope`, the manifest and the receipt's full `scope` retain every subject. Unknown published items and ordinary runs without selective policy retain the existing judgment requirements.

Changed source/status, changed ordinary receipt, missing provenance, or invalid certification removes this compatibility path and fails closure. Existing impact discovery, actual consumer maintenance, current source/context checks, and same-reviewer duties remain active. This is not a general published-item exemption or a new audit/review basis.

## Exact forward aggregation

For a subsequent native gate certification in a run with the existing authenticated gate-1 aggregation record, `certify` first verifies the prior certificate and the completed current native impact work. The new helper stages all 81 current contract inputs, the exact old live cache, the deterministic new cache, and the immutable prior certificate under content-addressed files. It never uses or expands the missing-preimage historical `3bb...` reference. Every old/new cache byte in this forward transition is available and hash-bound.

The NEW immutable certificate contains a typed `contract_aggregation` intent and its evidence, including the new absolute live-cache pin. The original relative historical pin remains untouched. The certificate intent is frozen before the live derivative is replaced; only after the exact cache replacement succeeds does the controller move the live certificate pointer. This is ordinary native certification output, not an owner history registry or a replacement review.

A crash between these writes leaves either the original valid live certificate or an explicitly resumable frozen new intent. The saved-certify path rechecks non-cache evidence, the precise old/new full cache preimage, every staged current contract input, current source guards and contexts, and completed native impact closure before finishing that exact cache write. Arbitrary cache edits and stale source/context/closure/metadata cannot resume. Active certificate verification requires the new exact live cache, never the pending old preimage. Historical input archives remain valid when later ordinary native work changes the mutable batch contracts; a saved-current retry still requires its exact inputs.

The aggregation supplies no source, consumer, audit, judgment, threshold or creation credit. Normal current reviews and all later gates remain required. The next ordinary `merge-contracts` gate reproduces the already certified current cache byte for byte. Default runs without this opt-in historical aggregation basis keep their original behavior.
