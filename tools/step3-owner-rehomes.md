# Guarded same-ID proved prerequisite rehoming

This proposal repairs a representation defect found by the actual frontier depcheck/fwdcheck. Five proved lemmas must move earlier within the existing one hundred pages. Their original native reader, refuter and Alpha obligation batches remain historical authority; source claims, source hashes at observation and catchers are never rewritten. The sixth helper is genuinely post-baseline and receives its first current owner-creation home separately.

`step3-owner-rehomes.mjs` records a separate version-one `owner-step3-same-id-proved-rehome-v1` registry at `research/RUN-step3-owner-rehomes.json`. It does not repurpose the unrelated source-only theorem-to-unproved-remark migration API or the less specific legacy `RUN-rehomed.json` receipt.

Registration requires explicit owner identity, timestamp, reason and exact named source/target page families. Hash-bound before/after frontier manifest archives must retain the same unique item inventory and page identities/owners/categories/orders. Every moved lemma must have its original immutable baseline owner and real pre/post-reader snapshot entries. Source bodies and semantic manifest fields remain equal; only page/batch placement, derived dependency levels and mechanical verification metadata may change. Contracts, including the actual current risk entries, must transfer unchanged. Registration checks that all these after-carriers match actual current files. No guessed original manifest or substituted frozen snapshot is allowed.

The Step3a-only manifest view projects those five IDs back to their original obligation batches. Source/contract/manifest fingerprints still come from each actual new home. In-run producer observations retain their original producer batch while their current proof-carrier lookup resolves through the guarded relocation. Missing originals, reader deletions, aliases and other IDs keep the existing checks. Incoming items do not manufacture reader/refuter/Alpha dispatch coverage. Existing counterexample and ID-migration support remains composed into the current scope code.

After registration the immutable receipt proves the historical relocation, not acceptance of future content. Current unique home/page ownership and all frozen archives remain checked. Later current additions are allowed only after registration and only when their IDs were absent from BOTH baseline item inventory and baseline existing files. All archived901 originals must remain present and uniquely owned, with the same frozen100page families. Registration still requires exact before/after/current inventories. New helper creation/audit gates remain due; a historical rehome receipt grants them no execution coverage. Later native source/contract repairs are allowed, but ordinary current subject seals still hash those real current carriers and become stale normally. No creation certification, audit, verdict, gate waiver or new execution coverage is produced. Genuine later native Steps3b/4/5 remain due.

Root applies/reviews the proposed code and metadata, transfers the current contract rows, then performs:

```sh
node tools/step3-owner-rehomes.mjs check --run RUN --evidence research/EVIDENCE.json
node tools/step3-owner-rehomes.mjs record --run RUN --evidence research/EVIDENCE.json
```

The read-only check rejects an unperformed relocation. Recording preserves the validated origin and refuses a different replacement. Root then stamps the unchanged original native obligations against their actual new current carriers and refreshes dependency-review ownership. Do not edit pre/post snapshots, original finding targets or historical obligation batches.

Validation: fifteen focused tests cover successful routing/carrier separation, frozen snapshot retention, reader deletion, altered Statements, altered contract/risk, added pages, duplicate owners, tampered archives, explicit-family escape, derived levels and later native repair without adopted acceptance. A syntax check also passes for the composed current scope proposal. This is a code/evidence proposal; no native registry has been written by its preparer.
