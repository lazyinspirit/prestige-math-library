# Incidental published citation context

`step3-owner-incidental-published-context.mjs` supports one opt-in contextual
ledger disposition, under `incidental_published_nonfatal_contexts` in the existing
version-1 `research/RUN-step3-owner-repair-evidence.json`. Absent or empty entries
leave the existing checks unchanged. Invalid nonempty entries fail the routing
check; they do not fall back to contextual acceptance.

The only supported case is run `machine-learning-all-101-2026-10-19`, batch 1,
existing defect `ml101-b1-3a-published-box-source`, published supplier
`thm-lebesgue-measure-of-a-box-of-every-kind`, and assigned consumer
`ex-singular-line-law-has-smooth-positive-time-density`. This is an incidental
citation alert genuinely recorded by native Alpha1, with no original reader
finding or additional routed obligation. The policy does not create either.

The exact active row must remain nonfatal, citation-misattributed, frontmatter,
nonfatal-recorded, and unchanged. The original successful immutable Alpha1
attempt, original report, original prompt and assignment have fixed authenticated
hashes. The current published supplier must be outside every current run
manifest. The singular-line consumer must have one current home, batch 1, owned
by the native batch-1 group, with the direct dependency in source and manifest.
Both sources must match their originally reviewed raw hashes and own-run archive
references. The current supplier explicitly assumes Countable Choice; the
consumer carries Countable Choice and Full AC.

The separate owner review binds the literal box-volume clause, choice premise,
consumer F3, consumer A2 and proof step 1.1. Root must have genuinely completed
the bounded use review before registering it. It records only that the current
use is sound, together with the pending bibliography correction. The published
maintenance paragraph must remain uniquely present and match a frozen own-run
quote archive. Unrelated appended published-ledger notes are permitted.

Registration uses the reviewed `registry-entry.json` and purpose-specific
`evidence/owner-use-review.json` in the staged packet. Do not register the older
`context-proposal.json`: its historical transcript references are not closure
inputs. All new reference objects use only own-run JSON/Markdown evidence. The
existing `ownerRepairEvidenceClosure` recursively freezes those bytes, including
source archives and the maintenance quote. It does not traverse the operational
log path string in the original native result. No freezer change is required.

The scope checker adds only this validated existing defect ID to its contextual
set. Original decisions, findings, observations, reports, ledger rows, source
bytes, group membership and native coverage remain unchanged. No source repair,
whole-supplier mathematical acceptance, certification, gate waiver or new native
review is supplied. The published bibliography remains pending maintenance.

Focused tests use isolated copies of the real authenticated records and current
sources. Run `node --test tools/step3-owner-incidental-published-context.test.mjs`.
They check the allowed exact case, default behavior, evidence freezing,
append-safe maintenance, and rejection of altered sources/records, wrong scope,
missing review/premises, fatal or fixed rows, and extra coverage/repair claims.
The archived run-specific fixture packet must remain available for these tests.
