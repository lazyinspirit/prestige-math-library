# Static Step-6 mechanical check map

This maps the rebuilt source to the old mechanical conditions; it is not execution evidence. No test,
check, gate, engine or cutover command was run. Original completed receipts and
native history remain untouched. The root must authorize and implement any live
cutover separately; installing the rebuild does not migrate a run.

Both engines emit four ordinary serial stages: `6-prepare-v3`,
`6-pathway-author-v3`, `6-final-validation-v3`, `6-finalize-v3`. Only the final
validation stage has a content gate battery. A failed battery retains its native
blocking authority and repair loop. After its genuine pass, the immediately next
native tool writes the concise report and commits. The final transaction is an
explicit typed exception, never `gatesWaived` or an empty gate array.

In the table, P means `tools/` for mathematics and
`tools/physics-support/` for physics; RUN is the actual run; manifest, auditor,
terminal-resolution and configured-judge argv remain generated by the ORIGINAL
source helper functions, whose definitions are preserved verbatim. G means the
single `6-final-validation-v3` battery, T means an assertion inside the real
report-and-commit transaction, and PREP means an actual deterministic mutator.

## Mechanical mutators and repair routes

PREP performs the actual defect-table render, touch endpoint, pathway placement
and seed. `prepare-final` performs actual metadata/render recertification,
judge-stamp application, proof-layout preparation, readiness write, mechanical
evidence reconciliation and validated-input snapshot in dependency order.
`prepareFinalIfChanged({ctx,executor,stage,physics})` in the shared helper: it waits until initial preparation has genuinely completed and writers
have drained, memoizes selected-source fingerprint plus repair round, and
refreshes derivations only after actual source/round changes. It must not launch
processes or rescan the corpus on every scheduling tick. Any actual repairs are
followed by fresh preparation and the entire G battery.

The contract repair function is copied verbatim from the original stage:
actual open contract rows determine owning batches; native outage clocks retain
their budget; owning Beta performs source-grounded contract rework; independent
Alpha certifies; original obligation dispatch overrides remain honored. It is
invoked for the primary and all advisory defect-ledger failures.

The obligation repair function retains the original due-row native dispatch,
recorded role/timeout/label, future unblock clocks and owner-held unresolved
rows. Both primary and advisory obligation failures reach it in the same repair
wave. A real pathway-closure failure can dispatch the existing Lead Alpha task;
zero pending briefs do not start a vacuous worker. Other failures retain the
existing mechanical repair table and unresolved mathematical/physics failures
remain visible for the owner to repair; no accepted claim or source narrows to
make a gate pass.

The old tree-clean repair committed immediately because its gate ran AFTER the
report/commit. That commit action is now owned ONLY by T; a failed preflight may
never call this obsolete early-commit repair. It blocks for scope repair, then
rechecks in G. A failed terminal transaction retries its actual tool receipt;
it cannot pass by running an unrelated command or adopting an old result.

The existing automatic model boundary remains unchanged for real Step-6
cognitive repairs. The generic executor and its native barriers, repair engine,
gate event recording and dispatch coverage are unchanged. The owner-supervised
math wrapper no longer adds a second metadata pass/pause around Step-6
bookkeeping; earlier stage owner boundaries remain intact.

## Runtime and historical boundaries

The helper APIs, planned-summary/preflight flags, report-dependent assertions
and source certificate binding are implemented together. No tests or validation
execution are claimed. A historical frozen run requires a separately authorized
guarded cutover; renaming completed stage state is forbidden.

## Shared implementation

The implementation includes
`tools/step6-finalize.mjs`, `tools/step6-prepared.mjs`, the physics finalize
wrapper and the narrow physics prepared-authorization branch. These APIs were
reviewed as source only, never executed for this rebuild. Preparation checks actual dependency-ordered
metadata and runs the real renderer once; that same actual scan materializes
the original native proof-layout schema. The final tool authenticates the actual
native ordered successful gate events and the immediate stage state, then writes
the deterministic response, runs only its cheap existing schema validator,
renders the concise report and invokes the shared `commitStep6` API. It does
not call legacy summary/evidence reconciliation or a later scientific battery.
The report assertions and actual file hashes remain recorded in its committed
native receipt.

`PRESTIGE_STEP6_STATE_DIR` selects the actual configured child runtime without
changing native plan argv. Stage construction registers `ctx.config.stateDir`
for imported hooks; every selected state file must owe the same run. The cold
`assertFreshStep6State` refuses historical Step-6 keys/current stage rather than
silently adopting earlier v2 coverage. Physics hotreload now uses its
`stagesForRun` wrapper exactly as mathematics does, retaining existing completed
prefix checks. No scheduler or gate execution behavior changed.

The physics layout scope now uses the same manifest/alias/actual-page agreement
and hash-bound extra published-context checks as the existing mathematics
selector. Historical touch logs remain bound evidence and cannot add unrelated
proof subjects. Explicitly authored/owned subjects must remain in the native
current manifests; published prerequisite context is hashed but not promoted to
an authored proof review. The final physics-content gate retains its complete
scientific checks and uses the scoped import-verification flag supplied by the
scoped import verifier.

## Commit and snapshot conditions

The scoped transaction preserves the old main-branch, safe-path, physical-file,
Git-ignore, conflict/submodule, hook/filter/environment, active-operation and
split-index guards. Scope policies retain exact supporting hashes, deletion
preimages, published repair/no-op authority, and inventory currency. Physics
uses its native local repair verifier and prohibits owning imported mathematics.
The known inert hook retains its exact source hash and absent-target check.

Exact operational resolver exclusions still validate their authority, supporting
evidence, protected-input disjointness, entry modes and raw symlink-target/tree
hashes. Only those explicitly selected directories are inspected; the library
is not a preservation inventory.

The old cross-boundary commit/preservation condition is enforced by constructing
HEAD plus only owned blobs and comparing every outside proposed/committed tree
entry. Foreign working files cannot be mutated by this operation: no checkout,
filters, commit hooks, blanket staging or foreign-file writes occur. The real
index lock, main ref compare-and-swap, exact owned current bytes/blobs and
outside staged entries/flags protect the transaction. The selected validated
frontier/context is rebound immediately before the ref update. Failures after a
landed commit remain held and never trigger reset/checkout or a false success.
These operation assertions replace the repeated whole-working-tree hash scans;
no post-commit scientific battery is launched.

The final touch endpoint uses `--step6-run RUN`: actual manifest subjects plus
published ownership claims receive both the unchanged mathematical and public
interface hashes from one read per carrier. Historical full snapshots remain
unchanged; earlier Steps1–5 keep their original snapshot behavior. Duplicate-label
and idempotent exact-byte checks remain. No foreign repair is inferred from a
frontier-only endpoint, and it does not expand proof subjects.

The final native receipt stays `ok:false` while the transaction is pending. Its
successful blob is prepared for the commit, but adoptable working-tree success
is materialized only after commit/index assertions pass. A crash before then
leaves a native blocker, including when the commit itself already landed.
