# Native interface-consumer reviewer continuity

A completed collected native repair report can establish a separate same-reviewer
consumer duty when its actually assigned repaired source changed Statement or
Definition, its source review/post/context and frozen before-statement hash match
the genuine collection event, and it reports an explicit `downstream_uses` string
for an actual direct consumer. Mere unannotated discovery creates no new duty of
this type. No `downstream_pending` field or review is added to the original report.

The controller derives `native_interface_consumer_obligations` and later genuine
`native_interface_consumer_coverage`. It authenticates the original report/pack,
collection, successful stable and immutable owner result, exact prompt identity,
source event/post/context and original phase-correct persistent session. The
current source and consumer guards authenticate an initially discovered edge;
frozen matching-source impacts and typed duties retain owed work if later edges
change. It never retrospectively attributes a new edge to an older source edit.

Planning selects the actual repairing lane and resumes that physical native
session. Current reviews from another lane/session or stale context supply no
same-owner coverage. Conflicting real owner/session identities fail closed rather
than selecting one and silently losing another duty. Ordinary supplier/interface
propagation, outside maintenance and other review obligations remain active.
Completed impact verification rederives the obligations and genuine coverage;
certification cannot close with another lane's review or a forged closure row.

## Recover an unused misrouted continuation

Use the existing `tools/step5-impact-recovery.mjs` mechanism after installing the
reviewed routing correction. It requires a paused/drained actual impact stage,
no live controller, no shared write lock, no successful or reported/collected
followup, and every source unchanged since the unused pack. It accepts no
separate authorization JSON; `--reason` must truthfully explain the planning defect.

```sh
node tools/step5-impact-recovery.mjs --run RUN --state-dir .autopilot/RUN --reason 'An unused continuation assigned a real interface consumer to a different owner; preserve originals and regenerate the genuine repairing-session continuation.'
```

Recovery preserves the original pack/tasks, prior progress and collected evidence
as immutable supersession history. It then invokes ordinary native advanceImpact
to produce the next unused ordinal with the corrected actual owner/session. Do
not rewrite a frozen pack or mark the unused work completed. Follow the ordinary
fresh current preparation and recertification before the next gate attempt.
The native controller may first dispatch the pending continuation; it holds again
after those writers drain, before any gate.

Native impact joins must discover all successor owner work before deciding that
a battery is ready. Only `5.2-impact`, `5.6-impact` and `5.9-repair` opt into
`nativeImpactProgressBeforeOwnerHold`. Both owner wrappers run their existing
native progress hook first, then apply the unchanged owner hold against the
updated unit inventory. Pending consumer work stays dispatchable without gate
permission; true final closure still pauses for current owner recertification.
A manually paused run never executes this progress hook. Other stages retain
their hold-first ordering, Step6 remains unchanged, and `beforeGates` and actual
gate permission consumption are unchanged. This ordering grants no review,
coverage, permission or external stage advancement.
