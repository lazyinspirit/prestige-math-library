# Native Step6 cutover and failed finalization refresh

The `cutover-step6` engine command owns the transition to the current Step6
suffix. `--refresh` may reopen an unfinished failed native v3 finalizer only
after authentic complete preceding preparation and gate events, a stopped or
paused/drained own controller, and proof that no final transaction landed.
It archives actual old state, events, results and authority; it creates no
coverage. The new suffix performs fresh preparation and the complete battery.

In addition to the two existing source/context refusals, refresh recognizes the
exact native pre-refusal `closeout: supporting path bytes differ from owner
authorization: PATH` only when PATH has an authenticated committed tooling-base
successor. Unknown failures, pending transactions and successful/committed
finalization evidence still require separate recovery.

The current exact ownership receipt for an `additional_paths` tooling entry
may be an `owner-reviewed-supporting-git-base-successor` with own `run`,
`authorized_by: owner`, `owner_identity: /root`, `coverage_created: false`,
ordinary exact `owned_paths`, and `supporting_git_base_successors`. Each proof
contains `path`, `original_head`, `current_head`, the exact ordered
`checked_descendant_commits`, `previous_policy`, `previous_working`,
`original_base`, `current_base`, `unchanged_patch_sha256`, a substantive
`reason`, and `coverage_created: false`. Archive references are
`{path,sha256}`, regular nonsymlink files in own-run research.

The previous policy bytes and its original ownership receipt must match their
actual preceding prepared-source pins, using SHA256 of `file\0` plus the
bytes. That prior ownership binds the exact old working bytes. Original/current
base archives must equal the real Git blobs at the authenticated old/current
HEADs. Current index must equal current HEAD with ordinary mode, stage and
flags. Current working bytes must satisfy the new exact policy and ownership.

The guard independently diffs original base to previous owned working archive
and current base to actual working file with Git's read-only, zero-context,
no-ext-diff/no-textconv/no-renames mode. After excluding file headers and only
normalizing hunk line numbers, both complete nonempty textual patches must be
identical and match the recorded hash. Added or foreign uncommitted edits are
not admitted. Hunk content and trailing function context are preserved.

Every intervening commit is still inspected. Only explicitly proven existing
`tools/` additional paths, excluding physics-support tooling, may have their
committed blob advance between the two exact approved endpoints. All other
owned item, page, published, research, helper and shared-fragment Git bases
retain the original strict projection checks. No whole-file grant to foreign
working changes or replacement of the original Git base is made.

Root first reviews an unexecuted successor-policy request, retains prior
receipts and evidence, and installs exact new ownership through an explicit
compare-and-swap. Root then uses the normal guarded refresh inspect,
authorization and execution flow. Refresh never retries the old battery as
current: policy/tool changes require actual fresh metadata/render preparation,
the full current battery, reporting and the native finalizer.
