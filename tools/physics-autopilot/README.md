# Physics workflow engine

Use `physics/WORKFLOW.md` for the six-step stage table, run controls, owner holds and evidence procedures.

The rebuild plan is `physics/research/workflow-rebuild-plan.md`. Step 1 performs complete initial authoring; Step 2 is the bounded Luna-max whole-batch scope/prerequisite loop. Planning generates group metadata; accepted plan synchronization is part of the Step-2 mechanical handoff. There are no separate assignment or splice stages.

Step-1 authoring fills the shared 30-worker budget from the entire pending queue,
prioritizing lower dependency levels. Cross-pair prerequisites never block an
author's start or remaining work. Slot refill is triggered by worker completion;
current supplier readiness remains a requirement of the drained Step-1 gates.

Current revision: `physics-six-step-v1-construction-scope`. Use fresh run state. The engine owns all transitions and enforces the shared 30-agent cap. See `package.json` for typechecking and focused test commands.

Run the scope-review controls from `physics/` through its `tools` symlink. The CLI resolves the symlink before dispatching `check` or `owner-resolve`; missing current batch acceptance fails with a nonzero exit code.
Scope repairers use the existing cognitive `authoring` job classification, so dispatch preflight permits their substantive proof and prerequisite repairs. Their batch ownership and bounded review history still apply.

For Root-approved missing mathematical pairs during unfinished Step 2,
`autopilot.mts prerequisites register --run RUN --state-dir DIR --request FILE`
adds separate native supplemental construction and ordinary new-batch scope
review. `prerequisites finish` completes an interrupted exact journal installation.
The stopped/drained boundary, committed original metadata, source ownership,
fresh import authority and no-backup transaction protocol are specified in
[physics/WORKFLOW.md](../../physics/WORKFLOW.md#supplemental-prerequisites-while-step-2-is-unfinished).
Registration writes no acceptance or retrospective Step-1 coverage. Without a
registry the existing stage/worker/gate descriptors remain unchanged.

Step 3 ends after independent batch readers, refuters and routed adjudicators, the exact post-3a baseline, and mechanical `3a-close` history freeze. The original adjudication gate battery remains the review boundary. There is no cross-batch review, unfinished-review continuation or impact-audit duty after that boundary; dependency levels prioritize initial authoring while independent review retains its own prerequisites. Historical Step-3b receipts remain historical evidence.

Within the Step-3 pipeline, ready downstream work gets available slots before
upstream work: adjudicators, collection tools, refuters, split tools, then readers.
Each batch still requires its predecessor receipts and artifacts, with no live
predecessor writer. Stage, role, and global caps include workers adopted after a
controller restart; the full group gate barrier remains in place.

One owner-authorized fresh Step-3 refutation per unit can be enabled with the same
hash-bound protocol documented in `../autopilot/REFUTER-COVERAGE-CONTINUATIONS.md`.
The new native refuter performs all scoped reads independently; original
coverage assertions are not accepted as proof of reading. The original report
and receipt remain archived, and normal collection and closure checks apply.
The Step-3 owner gate snapshot binds the continuation authority, original native
receipt/report/final-message evidence, and exact correction task. Dispatch-time
subject hashes remain historical; the snapshot separately binds live sources.
For same-finding comparison, an optional exact `items/SUBJECT.md — ` locator
prefix is ignored only for that same subject. Interior locations, defect labels,
severity/verdict compatibility and explicit sharing evidence remain required;
original locations and observed source fingerprints are never rewritten.

If an independently running producer changes a source after a reader observed
its current bytes, the private split helper can authenticate that historical
observation through `research/RUN-step3-observed-current-history-BATCH.json`.
This requires explicit Root authority, exact original finding objects, immutable
raw-source/report/receipt/attempt-log/final-message bindings, a native logged
source digest and source excerpts, and the ordinary live producer/reachability
route. Every evidence binding also appears in its `inputs` map, which the native
owner gate snapshot follows. The archived split-current source must equal the live source at split.
The original `observed_source` remains unchanged; the old raw-source-only
fingerprint is kept separate from the current producer/contract fingerprints.
The complete native receipt tail must authenticate the original report; clipped
tails are not supported by this bounded route. Ordinary current refutation,
adjudication, evidence bindings and gates remain required; this grants no source
edit permission or mathematical acceptance. Immutable evidence is rechecked
after split, while legitimate later repairs may change the live source.
`recoverLoggedSource` is a pure recovery aid for numbered native source output:
it accepts a proposed unchanged prefix only when the complete recovered bytes
reproduce the exact native logged raw SHA256. It writes no archive or authority.

The snapshot binds both local placements and the relevant current original.
Untracked, staged-only, changed, symlinked or ambiguous carriers remain blocked,
as do invalid identity, publication, classification and immutable pins. This
recognizes source placement only and grants no proof acceptance.

An immutable successful supplemental drift report with a bare `drift-applied`
line may receive a Root-authored format clarification at
`research/RUN-append-N-drift-format-clarification.json`. The typed receipt binds

It names exactly the added-edge delta against prepared declarations; every

Future supplemental tasks require same-line edge/move detail directly.

A later append uses the same paused, stopped, fully drained, unclosed Step-1

### Guarded Root repair during supplemental construction

`prerequisites repair-authorize --run RUN --state-dir DIR --request FILE`
and `prerequisites repair-complete` use the same native physics CLI as
`prerequisites register`. These commands write immutable repair receipts only;
they never edit sources, planning metadata, state, native results or acceptance.
Both require the latest unfinished `2-prerequisite-construct-N` stage paused,
controller stopped, every native/adopted/outside writer drained and all ordinary
boundary locks clear. A successful stage cannot be reopened with this API.

The authorization request is run-local JSON with `version: 1`, `run`,
`generation: N`, `reviewer: "/root"`, `writers_drained: true`,
`writer_scopes: []`, a substantive `reason`, nonempty `evidence` references
(`{path, sha256}`), exact committed `base_commit`, and distinct `items` IDs. Optional `metadata_changes` rows name exact
`{path, pointer, before_sha256, after_sha256}` source mirrors. Each pointer is
`/pages/P/items/I/FIELD` for the canonical plan or `/P/items/I/FIELD` for a
manifest; FIELD is only `deps`, `dependency_roles` or `statement`, and its item
must be authorized. Precompute the exact prospective value digests before
authorization using exported `repairValueDigest(value)`; it hashes compact JSON
`{present:true,value}` (or `{present:false}` for an absent field), never stores
preimage copies. Every declared after-value must equal the exact current source
frontmatter field, or the trimmed canonical Statement/Definition/Example body
for `statement`, selected by exact item kind (including Open problem).
Unlisted mirror edits are rejected.
Every selected carrier must be an original protected current-run draft. Current
raw bytes must match both the original generation and the exact Git preimage.
All original protected sources and full current manifests, plan and batch-level
ledger must likewise match that committed baseline. No copies or backups are
created. Existing Git objects and the immutable generation retain the preimages.

Authorization creates
`research/RUN-prerequisite-N-owner-repair-authorization.json`. Root then performs
only the admitted source repairs and necessary metadata consequences. The
completion request repeats the common fields (without `base_commit`/`items`)
and supplies one `reviews` row per authorized ID:

```json
{
  "id": "lem-exact-supplier",
  "before_sha256": "EXACT_ORIGINAL_RAW_SHA256",
  "after_sha256": "EXACT_CURRENT_RAW_SHA256",
  "interface_changed": false,
  "scientific_review": "Actual Root review of the corrected argument and hypotheses...",
  "focused_checks": "Actual focused source and formatting checks performed...",
  "scoped_use_justification": "Why these proof-only corrections preserve supplier uses, including the actual affected use checks...",
  "consumer_checks": []
}
```

`scientific_review`, `focused_checks`, `scoped_use_justification` and consumer
`reason` values each require at least 40 nonblank characters. Carrier id/kind/domain/library/aliases remain immutable. For changed public
contract bytes (the exact kind-specific section, deps/dependency roles, or physical contract),
`interface_changed` must be true and `consumer_checks` must cover the complete
union of the authorization-time and current transitive cones, each with `{id, sha256, decision: "accept" | "unaffected",
reason}`. Authorization stores only actual before-consumer IDs/path/hash records, never
source copies. Completion and replay recompute the current cone and require the
exact union and current consumer hashes; new consumers invalidate the receipt.
The native gate argv also binds a lightweight current identity/alias/dependency/
reference graph fingerprint, so new graph inputs invalidate old owner preparation
without an unrelated proof-body audit. Root owns those actual reviews. A textual correction can preserve
mathematical meaning; the review records that distinction. Proof-only repairs
require scoped supplier-use justification and any actual focused consumer checks,
not a fabricated full-cone proof audit.

Only predeclared exact source-mirror pointers and computed current-run item
`dependency_level` consequences may change in manifests/plan. Foreign plan
context rows and all other planning fields and inventories remain exact.
Source deps must match their rows, levels must match the full DAG, and the batch
ledger must match the current full graph. Completion runs the native current
full-frontier plan and dependency validators, retains immutable import pins and
old native history, and rejects any unlisted protected source change. Ordinary
content, contracts, coverage and all other gates still run afterward.

Completion exclusively creates
`research/RUN-prerequisite-N-owner-repair-completion.json`. A pending or stale
repair blocks supplemental construction. Receipts and all request/evidence,
source/metadata and checked-consumer paths enter native `ownerReviewInputs`,
including receipt absence before admission, so previous owner preparation loses
currency. Root must freshly prepare and run the full ordinary battery. Neither
receipt closes a hold or certifies proof acceptance. Failure before a receipt
write leaves no new receipt; an interrupted/partial exclusive receipt fails
closed for inspection, with no backup restoration or implicit replay.


### Reconcile completed supplemental authors' metadata

Root can run `prerequisites authored-metadata-adopt --run RUN --state-dir DIR
--request FILE` at the same paused/stopped/drained unfinished supplemental
boundary, **before** original-source repair authorization. This performs no
source edit. Eligible `items` are a nonempty subset of the generation's new
items, never the original frontier. The request uses the common version/run/
generation/reviewer/reason/writers/evidence fields, an exact committed
`base_commit`, and `metadata_changes` with the same value-digest envelope and
exact JSON-pointer convention as original repairs. The committed new-manifest
baseline must match the immutable generation. Root installs its proposed
metadata mirrors before invoking this guarded admission; until admission,
ordinary construction protection rejects those changed manifest bytes.

Allowed selected source mirrors are `statement` (the exact kind-specific public
section), `sources`, `title`, `deps`, `dependency_roles`, `proof_strategy` and
`provenance`. Fields must equal actual current source data, with exact expected
before/after digests. Inventory, pages, original rows, id/kind/domain/library and
all other scope fields remain fixed; only computed new-item numeric levels may
also change. Root's same-owner review establishes that the full approved scope
is preserved by any author clarification, rather than a mechanical assertion of
semantic equivalence. Each `reviews` row has `id`, current `source_sha256`,
`scope_preserved: true`, substantive `scientific_review` and `reference_review`
(including actual reading limits), and exact current full-cone `consumer_checks`
with the same current-hash/disposition/reason schema as original repairs.

Every affected batch must have its actual native beta result, a matching ended
successful dispatch/attempt, exact role/label/run/covers, and successful untimed
result. Missing, failed or still-running authors cannot be adopted. The helper
runs plan/dependency validation for all new generation pages/items with their
full prerequisite context, and current computed-level checks, then
exclusively creates `research/RUN-prerequisite-N-authored-metadata.json`. This
receipt binds the actual sources, Root reviews, references and native results;
it overrides only the new batches' effective manifest hashes. Original 69 rows
and sources gain no edit license, and no readiness, coverage, proof acceptance,
owner hold or native history is fabricated or closed.

Root commits those actual accepted metadata bytes before original-source
`repair-authorize`. The latter recognizes the authenticated effective new-batch
baseline and separately owns its admitted old-source consequences. Both
immutable receipts coexist; the initial generation remains unchanged. Receipt
absence/presence, request/evidence/source/native-result paths and relevant
consumer graph projection invalidate previous owner preparation. Replay checks
current source mirrors, consumers and native result ownership; later changes
stale the receipt. Fresh ordinary owner preparation and the full battery remain
required. Interrupted exclusive receipt writes fail closed without backups.


### Add missing old-page prerequisite context under the existing repair guard

Original-source `repair-authorize` optionally accepts `pages: [PAGE_ID, ...]`
in addition to its scientific item list. Each page must be an original registered
protected draft at its exact category/path, with current raw bytes matching the
immutable generation and committed Git preimage. New pages, published pages,
foreign pipeline markers and unregistered carriers receive no edit license.
The authorization stores `page_sources` hashes separately from item sources.

The sole permitted page source change is additions to the existing explicit
frontmatter `requires` sequence. Existing entries and their relative order must
be preserved; entries remain unique. The complete body and every other source
byte outside that YAML field remain exact, including inventory and order. Each
added target must have a real unambiguous published mathematical or current-run
mathematical home in the current plan, and its actual item inventory must contain
a dependency used by a source item on the repaired page. Local published math
homes are valid context without being immutable import snapshots; no supplier
source is modified by this permission.

Exact `metadata_changes` pointers `/pages/P/requires` (plan) or `/P/requires`
(manifest) bind before/after value digests and must belong only to authorized
pages. Both manifest and plan lists must match the exact current page source.
Completion also requires `page_reviews`, one row per page: `id`, exact
`before_sha256`/`after_sha256`, substantive `scoped_use_justification` for the
actual dependency-home additions, and `focused_checks` confirming preserved
body/inventory/other metadata. These are reading-context checks, not a claim of
new scientific interface review. The existing immutable completion receipt binds
these sources plus current used item/supplier/home hashes as `page_context`;
replay rechecks the additions and exact context. Native owner inputs bind them.

New-author metadata admission validates only its actual new generation subjects
and full prerequisite context. Known old-page defects remain unresolved, and
that admission grants no proof readiness or acceptance. Original repair
**completion still validates the full current run frontier**, including every
old page, after all admitted old source/page/metadata repairs. The subsequent
full supplemental native battery and every ordinary gate remain unchanged.
