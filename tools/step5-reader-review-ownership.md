# Step 5 same reviewer consumer obligations

A consumer may owe reviews to several actual supplier reviewers. A single item
owner cannot represent those duties. `advanceImpact` therefore keeps the
original admitted concern ownership separate from a set of required reviewer
lanes for each affected frontier item.

The native derivation starts from the original frozen `reader_concerns` and
`reader_concern_owners`. Only actual collected Statement/Definition changes
propagate to direct dependency/reference consumers. The changing supplier's
own original native report identifies its actual repairing lane. A native
authored prerequisite event is recognized only with its explicit validated
creation row and an absent original carrier. If an affected
consumer itself changes its interface, its actual repairing reviewer owns that
next boundary. Unchanged interfaces do not propagate. Earlier frozen obligations
and recorded direct impact edges remain available when a later edit changes the
graph. Published/outside maintenance retains its separate native route.

For each item/lane obligation, coverage comes from that lane's exact original
native report and successful dispatch, bound in its unchanged collected receipt.
The report review must still match the actual current source and dependency
context. The dispatch must retain the actual successful original persistent
session in `.autopilot/RUN/step5-reader-owner-sessions/uN`. Later native passes
must bind and resume that same session. A different lane's review cannot count,
and a later source or context change makes an earlier review stale. An ordinary
review from a different fresh session is ignored for this duty. A real review
from the exact original persistent session may count even if the item acquired
its obligation after that pass was prepared. A pack explicitly claiming a
selected reviewer must retain its exact original session binding; an invalid
claim fails closed even when its review is now stale.

A followup pack records only the necessary routing data:

- `reader_concern_owners` preserves original concern ownership.
- `reader_review_obligations` maps each affected item to its required lane set.
- `reader_review_owners` selects one currently owed lane per assigned item.
- Existing `reader_owner_sessions` and `input_evidence` bind the genuine prior
  native result and session used by each selected lane.

The selected lane is the first missing lane in sorted order. Each item appears
in exactly one lane per pass. Other owed lanes execute in subsequent native
passes after all writers drain. All obligations are recomputed after every pass;
if a later reviewer changes a source or interface, stale earlier coverage is
queued again. Existing no-progress protection compares both assigned items and
their selected genuine reviewers, so another owed reviewer is allowed while a
true duplicate at unchanged inputs still holds.

Completed closure records the derived obligation set and the exact native
report/dispatch/session/review digest satisfying every pair. Closure verification
recomputes both duties and current coverage from the preserved native inputs.
Certification uses that verification, including when reusing a saved certificate.
These records grant no new mathematical review, worker coverage, defect
resolution or gate waiver. Original packs, reports, receipts, decisions and
verdicts remain immutable; all ordinary closure and gate requirements remain.
